### Дослідження структури БД
* [ ] Які первинні ключі у таблиць Album, Artist, Track? Чи є вони автоінкрементними?
* [ ] Яка таблиця зберігає інформацію про зв’язок між клієнтами та купленою музикою? Які стовпці з'єднують її з треками або альбомами?
* [ ] Скільки різних країн представлено в таблиці Customer?
* [ ] Який зв’язок між таблицями Track та Genre, і як він реалізований у схемі?
* [ ] Які таблиці містять інформацію про працівників, і як визначаються їхні ролі чи посади? Чи існує якась ієрархія підпорядкування?
### Дослідження даних (агрегації + фільтрування)

* [ ] Які альбоми достатньо великі, щоб виправдати вищу ціну?
* [ ] Перелічіть ID альбомів з 5 або більше треками — вони можуть бути кандидатами на преміальну ціну.
* [ ] Як географічно розподілена наша клієнтська база?
* [ ] Порахуйте кількість ID клієнтів у кожній країні. Додайте поле для позначення типу країни в залежності від кількості клієнтів (Мала, Середня, Цільова)
* [ ] Які музичні жанри мають найдовшу середню тривалість треків? 
* [ ] Визначте жанри, де середня тривалість треків перевищує 250 000 мс — корисно для планування списків відтворення або ліцензування.
* [ ] Які представники служби підтримки мають найбільше клієнтів?
* [ ] Використовуючи таблицю Клієнти, підрахуйте, скільки клієнтів призначено кожному представнику служби підтримки (за допомогою поля «SupportRepId»). Це допомагає визначити розподіл робочого навантаження між співробітниками.
* [ ] Хто наші найцінніші клієнти?
Для кожного ID клієнта вкажіть його загальні витрати та кількість покупок. Відфільтруйте, щоб отримати тих, хто витратив понад 20 доларів.
